## 추가 감정 후보

### 긍정 계열

| 감정  | 설명                         | 기존 감정과의 차이          |
|-----|----------------------------|---------------------|
| 감사  | 고마운 마음, 일기 앱에서 감사 기록 수요 높음 | 행복보다 대상이 명확한 감정     |
| 설렘  | 기대감, 두근거림                  | 기쁨은 현재, 설렘은 미래 지향   |
| 뿌듯함 | 성취감, 자기 칭찬                 | 만족은 상태, 뿌듯함은 성취 기반  |
| 평온  | 의도적으로 편안한 상태               | 보통은 무감정, 평온은 긍정적 안정 |

### 부정 계열

| 감정  | 설명                    | 기존 감정과의 차이        |
|-----|-----------------------|-------------------|

| 질투  | 비교에서 오는 감정            | 불쾌와 달리 특정 대상 향    |

### 복합/미묘한 감정

| 감정  | 설명                   | 기존 감정과의 차이            |
|-----|----------------------|-----------------------|
| 그리움 | 사람/장소/시간을 떠올리는 감정    | 외로움은 현재, 그리움은 과거 지향   |

### 우선 추가 추천 (Top 5)

3. **뿌듯함** — 성취 기록 동기부여

## 피처: 감정 복수 선택 (최대 4개)

### 배경

현재는 하루에 감정 1개만 선택 가능하지만, 실제로 하루 동안 여러 감정을 느끼는 경우가 대부분이다.
복수 선택을 지원하면 더 풍부한 감정 기록과 통계 분석이 가능해진다.

### 요구사항

- 일기 작성 시 감정을 **최소 1개 ~ 최대 4개** 선택 가능
- 선택 순서에 의미 부여: **첫 번째 = 대표 감정** (캘린더/통계에서 기본 표시)
- 4개 초과 선택 시 안내 메시지 노출

### 영향 범위

#### DB 스키마

- 현재: 일기 1건당 이모티콘 ID 1개 (1:1)
- 변경: 일기-이모티콘 매핑 테이블 추가 (1:N, 최대 4)
- `diary_emoticon` 테이블에 `order` 컬럼 추가 (선택 순서)

#### UI 변경

- **일기 작성 화면**: 이모티콘 선택 바텀시트에서 복수 선택 UI
    - 선택된 이모티콘에 순서 번호 뱃지 표시
    - 선택/해제 토글 방식
- **캘린더**: 대표 감정(1번째) 표시, 탭 시 전체 감정 표시
- **감정 통계 차트**: 복수 감정 반영한 집계 로직 수정
- **PDF 내보내기**: 복수 감정 표시 대응

#### 데이터 레이어

- `Diary` 도메인 모델: `emoticonId: Int` → `emoticons: List<Emoticon>` (최대 4개)
- `DiaryRepository`: 저장/조회 로직 수정
- SQLDelight 마이그레이션 스크립트 작성 필요

### 마이그레이션 전략

1. 기존 데이터: 기존 단일 이모티콘을 `order = 0`(대표 감정)으로 자동 매핑
2. 하위 호환: 대표 감정만 읽는 기존 로직은 `order = 0`만 조회하면 동작 유지
