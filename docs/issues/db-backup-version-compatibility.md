# DB 백업 파일 버전 호환성

- **상태**: 참고 (DB 버전 업그레이드 시 대응 필요)
- **날짜**: 2026-03-31

## 요약

DB version 1에서 생성한 백업 파일을, DB 버전 업그레이드 후 복원할 때의 호환성 이슈 정리.

## 현재 구조

- 백업은 JSON 기반 (`BackupManifest`) — DB 파일 직접 복사가 아님
- 복원 시 `DiaryRepository.saveDiary()`를 통해 한 건씩 insert
- 따라서 DB 스키마 버전과 무관하게 동작

## DB 버전 업그레이드 시 체크리스트

| 항목 | 설명 |
|------|------|
| `BackupDiary` 새 필드 | nullable 또는 default 값 지정 (구버전 JSON 호환) |
| `BackupManifest.formatVersion` | 스키마 변경 규모에 따라 올릴지 판단 |
| `DatabaseMigrations.migrate()` | ALTER TABLE 등 마이그레이션 쿼리 작성 |

## 위험 시나리오

| 시나리오 | 위험도 | 설명 |
|---------|--------|------|
| 새 컬럼 추가 (NOT NULL, 기본값 없음) | 높음 | v1 백업에 해당 필드 없으면 NOT NULL 제약 위반 크래시 |
| 컬럼 삭제/이름 변경 | 중간 | v1 백업에 있던 필드 유실 가능 |
| 컬럼 타입 변경 | 중간 | 역직렬화 실패 가능 |
| 테이블 분리/정규화 | 중간 | 복원 로직 자체 수정 필요 |

## 결론

현재 JSON 기반 백업이므로 즉시 대응 불필요. DB 버전 올리는 시점에 위 체크리스트를 함께 챙기면 충분.
